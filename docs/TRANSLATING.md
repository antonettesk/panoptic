# Translating Panoptic

Panoptic ships in English, Español, Français, Deutsch, Português (Brasil), 日本語, 简体中文, العربية and हिन्दी. New languages and corrections are very welcome.

## Add a language

1. Copy `ui/src/i18n/locales/en.ts` to `ui/src/i18n/locales/<code>.ts`, using a BCP-47 code such as `it`, `ko` or `zh-TW`. Change the header to:

   ```ts
   import type { Messages } from './en';
   const it: Messages = { /* … */ };
   export default it;
   ```

   Typing the object as `Messages` makes TypeScript reject missing or unknown keys.
2. Translate every value. Keep `{placeholders}` exactly as they are. Their order may change.
3. Register the language in `ui/src/i18n/index.tsx`: import it, add it to `CATALOGS`, and add an entry to `LANGUAGES` with its native name, its English name, and `dir: 'rtl'` for right-to-left scripts.
4. Run the checks:

   ```bash
   npm run test -w ui
   ```

   ```bash
   npm run typecheck -w ui
   ```

   The catalog test fails on any missing key, empty value or placeholder mismatch.
5. Review the app in your language. In a browser this works with demo data:

   ```bash
   npm run dev -w ui
   ```

   Look out for truncated labels and RTL layout issues.

## Style

- **Keep these terms in English:** product names (Panoptic, AWS Security Hub, MITRE ATT&CK), technical identifiers (PID, SHA-256, ASFF, CLI), and command-line text.
- **Keep it short:** button labels should be short verbs.
- **Use a neutral, professional tone,** with the formal register where your language distinguishes one (e.g. *Sie*, *vous*).

## What is not translated

Findings, evidence and recommendations generated by the engine stay in English on purpose, so they can be searched, shared with incident responders and matched against threat intel verbatim. The UI shows a note explaining this.
